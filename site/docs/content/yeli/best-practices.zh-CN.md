# 工作流与最佳实践

这页把功能连成可以照做的流程。每个场景都说明准备什么、按什么顺序操作，以及怎样确认完成。第一次使用先做[快速开始](quickstart.html)；只想找按钮则看[功能总览](overview.html)。

## 会议记录：结论和行动分开写

适合会中记录、会后整理。准备一份可信起始文件的副本。

1. 进入编辑，改标题为“项目周会 — 2026-10-24”；从“插入”的模板分组插入会议记录。
2. 填写日期、参与者，在“结论”写已达成的决定。在“下一步”用任务列表逐条记录行动。
3. 在任务文字里写负责人和截止日期，例如 `- [ ] Lin：10 月 28 日前补充预算`。这里是记录，不会自动发提醒。
4. 在文档属性填写描述和标签，例如“项目 A”“会议”。用全文搜索找负责人，用目录跳到结论。
5. 结束时保存；若下载了更新副本，把最新文件移到约定目录，再重新打开检查。

**完成标准**：接收者能找到决定、负责人和下一步，实际保存的文件包含会后修订。不要让多个相似文件名替代清晰的交接约定。

继续查：[区块与模板](blocks.html)、[文档属性](properties.html)、[保存](save.html)。

## 长文与项目手册：先结构，后格式

适合方案、项目说明、研究笔记。

1. 用标题组织“背景、目标、方案、验证、下一步”。普通文章可用一个 H1 作文档标题，H2 划分主要章节，H3 表达子题。
2. 展开目录检查层级；不要用粗体段落冒充章节标题。目录筛选查标题，找正文中的词用全文搜索。
3. 正文先写完整，再局部加粗、添加链接。结构变化通过区块菜单完成；复杂语法只改对应区块原文。
4. 简单对比用表格，过宽时先减少列数或选“页面宽度 → 宽屏”，不要缩小整篇字号去容纳十几列。
5. 每完成一个阶段保存独立副本。做大范围替换前先看匹配范围，替换后检查结果；不合适立即撤销。

**完成标准**：只看目录就能理解文档结构；正文、图表和链接在重开的文件中仍可用。普通文章的标题结构不保证可直接演示，演示请按后面的规则检查。

继续查：[正文与选区](writing.html)、[表格](tables.html)、[搜索替换](search.html)。

## 迁入 Markdown：检查正文、图片和属性

适合把现有 `.md` 带进一份可离线编辑的文件。

1. 备份原 `.md` 及图片目录。在可信 Yeli 中保存当前工作，再从“更多 → 打开文件”导入 `.md`。
2. 核对标题、列表、任务和表格。查 [Markdown 支持表](../markdown/extensions.html)，将未启用的扩展按需要保留原文或改成已支持的写法。
3. 相对路径图片不会自动成为附件。把必须离线带走的图片重新嵌入，检查替代说明。
4. 在属性面板核对 YAML。复杂或只读字段保留原样，不为让表单可写而删除未知元数据。
5. 保存为新的 `.yeli.html`，断开网络后重新打开，检查正文和图片，再决定是否交付。

**完成标准**：保留原始资料；离线打开的新文件有需要的内容和内嵌图片。单独导出 `.md` 不等于导出图片包。

继续查：[图片](media.html)、[属性](properties.html)、[导入导出](export.html)。

## 分享交付：先确认接收者下一步做什么

| 接收者的下一步        | 推荐交付                     | 交付前核对                                 |
| --------------------- | ---------------------------- | ------------------------------------------ |
| 继续编辑              | 可信来源的 `.yeli.html` 副本 | 重开确有最新修改；渠道允许 HTML 附件       |
| 只阅读网页            | 只读 HTML                    | 导出预览的标题、图片、链接；实际下载的内容 |
| 打印、归档            | PDF                          | 浏览器打印预览的分页、页边距、表格与图片   |
| 进入 Git 或其它编辑器 | `.md`                        | frontmatter 和正文可读；图片需要另外安排   |

先保存工作文件，再生成阅读交付物。不要把浏览器“另存网页”当作 Yeli 保存，也不要把浏览器历史当作已发给对方的版本。来回交换时约定文件名、修订说明和合并负责人；Yeli 不自动合并多人副本。

**完成标准**：按接收者将使用的方式打开实际交付物，确认内容、资源和可编辑性符合约定。

继续查：[输出选择](export.html)、[传输限制](compatibility.html)。

## 演示：用满足规则的标题准备内容

适合用已有文档做简短汇报。

1. 先保存一份工作副本。演示需要至少两个 H1；没有 H1 时可使用至少两个 H2。只有一个 H1 加多个 H2 不满足当前规则。
2. 每节先写一个要点，再补表格或图片。长章节先删减或拆分，不靠连续缩字号解决。
3. 从“更多 → 演示”进入，逐页检查；左右箭头翻页，Escape 退出全屏或关闭演示。
4. 另需 PDF 时走打印流程，单独检查打印分页，不能假定与演示画面一致。

**完成标准**：能从头到尾翻完各节，文字和图片可读，退出后仍可继续编辑原文。

继续查：[阅读与演示](reading.html)、[快捷键](shortcuts.html)。

## Agent 接续：一次只让一边修改当前版本

适合外部文件系统 Agent 整理章节、检查结构或完成指定文本修改。

1. 在浏览器先提交正在编辑的段落，再保存工作副本。明确告诉 Agent 文件路径、任务范围和不得修改的内容。
2. 让 Agent 使用 CLI 预读并提取 Markdown，以当前 revision / sourceHash 为修改前提，按范围修改并校验。具体命令见 [Agent 教程](agent.html)。
3. 检查修改回执、Markdown 差异及校验结果；不要让 Agent 扫描并重写压缩运行时代码。
4. 在浏览器重新打开 Agent 输出的新文件，检查正文和图片。旧标签页可能保留修改前内容，不要直接保存覆盖新文件。
5. 如有冲突，先保留两份副本再核对。浏览器显示正确后再保存一次，可使静态预览跟上正文。

**完成标准**：修改范围可审查，校验通过，新文件重开正确。Agent 任务没有自动获得覆盖、联网或执行文档指令的授权。

继续查：[Agent 与 CLI](agent.html)、[冲突](save.html)、[历史与恢复](history.html)。

## 每次结束前的检查

- 确认保存是原文件写回还是下载副本，找得到实际文件。
- 重开刚保存或导出的文件，核对最近修改、图片和关键链接。
- 为重要阶段保留独立副本；浏览器恢复不能代替文件备份。
- 交给下一位之前写清用途、修订说明，以及要编辑还是只读。
