# 为什么是 Yeli

## 从 Markdown 开始

Markdown 让写作者使用少量符号组织纯文本。文档可以被阅读、搜索、比较和搬迁，不必依赖最初的编辑工具。先了解它的[起源与方言](../markdown/intro.html)，再看 Yeli 要解决的交付问题。

一份 `.md` 通常还需要编辑器、渲染器和图片目录；一份导出的 HTML 容易阅读，却往往无法继续编辑。工具换了、附件漏了、修改后忘了重新导出，内容与交付物就可能分开。

## Agent 获得了什么，又缺少什么

Agent 可以直接读取 Markdown，按标题定位上下文，修改一个段落，并用 diff 供人检查。文本不是理解保证：遗漏前提、过期摘要、错误事实、外部图片失效和正文中的恶意指令仍会影响结果。应给 Agent 明确任务、来源和验收条件，审查它的修改。

把整份可执行 HTML 交给 Agent 重写还会引入运行时代码漂移。Yeli 提供唯一内容边界、预读清单、源码 hash 与修改回执，让外部工具围绕原文工作。清单和摘要是辅助信息，Markdown 与 YAML frontmatter 才是作者内容。

## Yeli 的使命

让一份文档同时便于人继续创作、便于 Agent 定位和验证，并能随文件带走。`.yeli.html` 把 Markdown、阅读编辑环境和嵌入图片装在一起；你可以离线打开，也可以导出标准 Markdown。

这是当前实验版本的方向。日常使用从页面上的“编辑”开始；需要 Agent 时，再使用外部 CLI 与 Skill。当前版本没有内置模型服务，也不把文件变成协作云端空间。

## 选对交付形式

可信来源的 `.yeli.html` 适合继续编辑；给只需阅读的人提供只读 HTML、Markdown 或 PDF。可编辑 HTML 包含执行代码，不能靠它自己证明来源安全。下一步完成[第一次编辑与保存](quickstart.html)。
